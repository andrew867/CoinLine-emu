CoinLine Terminal Emulator for Windows x64
=========================================

1. Extract the entire ZIP to a writable folder. Open that folder in Explorer.
2. Double-click Start OEM.cmd for the 2-line terminal or Start Graphical.cmd
   for the 11-line terminal.
3. Click the emulator window so it receives keys. Esc closes the emulator.

The portable folder includes the CO simulator and its Python runtime. With blank
SIP settings it answers the lab toll-free call locally. The OEM terminal starts
blank on its first launch. Close the emulator and copy data/oem/nvram to the same
location in the new package to keep an installed terminal when upgrading.
The graphical launcher has separate battery, flash, configuration and logs
under data/graphical. Both launchers can run at the same time. Give them
different 10-digit terminal wire IDs and appropriate NCC table assignments.

Graphical update from cb6be6c988bf to 33eaa2644e20: close the old emulator
normally after INSTALL, then extract the new package to a separate folder.
The launcher separates saved state by full firmware digest. To retain the
installed terminal, copy coinline-graphical.ini if present and copy the
existing battery, nvram and coin files from the old profile's
11line/nvram/cl_millennium directory to the corresponding new digest
directory. Do not copy program_flash; the new image supplies its own seed.
Both profiles' full directory names are:

  data/graphical/multipay-v1.3-cb6be6c988bf57818bd25ed4cc0922f23c45429cba2fc81919203decb5fe603d/11line/nvram/cl_millennium
  data/graphical/multipay-v1.3-33eaa2644e20a41b7179195ee698d2e552d066d29b05377381245864dff7d9e1/11line/nvram/cl_millennium

Copy only to a new, empty destination. Keep the original state as a backup.
This exact retained-state transition passed startup, eight pickup/hangup
cycles and advertising resume. A fresh INSTALL on the advertising-corrected
image is still a separate qualification test.

Package.txt tells you whether this copy includes local ROM inputs. If it does
not, supply your authorized images at the following paths.

  firmware/oem/flash.bin (256 KiB)
  firmware/graphical/flash.bin (1 MiB, for Start Graphical.cmd)
  roms/cl_millennium/voice_u16.bin and voice_u26.bin (1 MiB each)

For other firmware, set the flash paths and hardware profile under [hardware]
in the corresponding INI file, or pass --firmware, --flash1, --rompath and --hardware on the
command line. Use --check to verify selection and the mapped flash hash before
launch. Available profiles include multipay-v1, multipay-v1-dual-flash,
multipay-v1.1, multipay-v1.3, desk-rel1, desk-rel2, card-only and coin-basic.
The V1.1 and V1.3 presets route the magnetic reader through DMA channel 1.
  For Coin Basic, --portable-display attached connects the temporary VFD for
  Craft. Exit, then use --portable-display detached for normal operation.
  For compatible later-board graphical firmware, --display 11line selects
  the large display and its six side keys and four navigation keys.
  The default auto selects the display from the verified firmware registry,
  falling back to 2line for conventional firmware.
See the project runtime guide for the acceptance gates on these presets.

Keep packages that contain local ROM inputs private. The ZIP includes no saved
terminal memory, SIP credentials, or site data.

For independent SIP accounts use coinline.ini for Start OEM.cmd and copy
coinline-graphical.example.ini to coinline-graphical.ini for Start Graphical.cmd.
Their default SIP ports are 5087 and 5088, respectively, and their dynamic
RTP ranges are 10000-14999 and 15000-19999. Do not reuse fixed SIP/RTP ports or
the same registrar account if you want simultaneous independent calls.

For 4K displays, run from Command Prompt:
  "Start OEM.cmd" --scale 2
  "Start Graphical.cmd" --scale 2
or use --maximize to fit the monitor work area. To retain the setting, set
window_scale = 2.0 under [display] in the corresponding INI file. The terminal
keeps its native artwork aspect ratio.

First INSTALL
-------------

Keep CoinLine Server running while you install. The default NCC listener is
127.0.0.1 TCP port 4000. Use a lab terminal record whose wire ID matches the
10-digit line number you enter. Assign the table set for the firmware's terminal
family. The default MTR 1.9 lab set includes the synthetic magstripe policy and
the free-call screening entries.
If you already have the working lab assignment, reuse it. CoinLine configuration
and service startup are managed separately from this emulator.

1. At Out of service, lift and replace the handset with H if needed. Enter
   CRASERV on the keypad as 2727378. Enter the craft PIN and press *. Then use
   K to unlock, C to open the housing, and # to start INSTALL.
2. At the CO check, let Go offhook sit for about six seconds before pressing H.
   If you lifted early and the display stays on Go offhook, replace the handset
   and lift it again. At Completed 00, press *, then replace it when prompted.
3. Enter the terminal's 10-digit line number, then the 10-digit test serial,
   then the NCC number. Save each field with *. The decimal number for local
   NCC at 127.0.0.1 is 2130706433.
4. Follow the answer supervision prompts. Lift with H, wait for Completed 00,
   press *, and replace with H when requested. Press * to start the NCC download.
5. After the download completes, press * and follow the keypad test. Lift the
   handset and press the requested controls, then replace it. Press P or click
   the card reader to insert, read, and remove the synthetic test card. Press *
   to continue after the card passes.
6. Use V, B, and M for nickel, dime, and quarter as prompted. Press * at Completed.
   When the terminal says Install is complete, close it with C and lock it with
   K. Check the lower-left indicators for Housing Closed, Lock Locked, and Coin
   vault Closed. It should show Please lift receiver. Later boots use the saved
   installation.

Some later firmware has a separate smart-card test and two calibration coins
followed by an escrow test. Use [ to insert the synthetic contact card and ]
to remove it, or click the contact action button. The synchronous contact test
passed on the later reference terminal with the previously qualified generic
contact fixture. That evidence does not qualify the changed synchronous default.
Other firmware may still report a failure. Follow the firmware's continuation prompt.
Allow the refund and collection tests to finish before pressing * again.

The optional smartcard-async-t0-lab.json and smartcard-async-t1-lab.json fixtures
are generic read-only native serial application tests, not historical payment
cards. The full graphical images (SHA-256 prefixes 996a8ac5e81d,
cb6be6c988bf and 33eaa2644e20) default to smartcard-async-contact-atr-lab.json for their
asynchronous contact diagnostics. Earlier images retain the synchronous
default. Override smart_fixture
in the profile INI if you deliberately want a different fixture.

On later boards, optionally set sam_slot0, sam_slot1 or sam_slot2 under
[cards] in the profile's INI to a generic read-only async contact fixture.
For the full graphical contact diagnostics, use
fixtures/cards/smartcard-async-contact-atr-lab.json for each desired slot.
For a generic module application transport test, use
fixtures/cards/smartcard-async-module-lab.json. Leave the
positions blank to emulate no installed module. These fixtures are separate
from the customer card and do not provide historical payment authorization.
For a programmable synchronous EEPROM contact bench, set smart_fixture to
fixtures/cards/smartcard-sync-gpm103-contact.json in [cards]. This replaces
the primary fixture only and retains the test pattern across restarts.
The bounded pattern is not an original chip-capacity declaration.
The independent LAB ledger utility is available at app/lab_purse.py. Run
runtime\python.exe app\lab_purse.py --help for its local request interface.

Controls
--------

  H / handset button   lift or replace handset, also clickable on the photo
  0-9                  keypad digits
  Shift+8 or numpad *  keypad *
  Shift+3 or numpad /  keypad #
  = / -                volume up / down
  L / N                language / next call
  Q W E R T            quick-access positions 1 through 5, also clickable on the panel
  Y G J X Z            positions 6 through 10 on a ten-button profile
  K / C / A            lock / housing / cash vault, also clickable on the LEDs
  P or card reader     insert, read, and remove the synthetic magstripe card
  [ / ]                insert / remove the synthetic smart card
  F / D                next magnetic / smart test card (or click its name)
  V / B / M            insert nickel / dime / quarter

The graphical example INI selects the nine-window regional validator.
For an existing INI, set coin_validator = regional-nine under [hardware]
when its downloaded coin table uses that calibration. The three-slot or
board-default setting remains appropriate for the original earlier fixture.

The card wallet shows the selected card and actual reader state. The second
magnetic fixture is an intentionally invalid-checksum test; the second
contact fixture is a generic read-only transport test. Set mag_fixture_2
through mag_fixture_8 and smart_fixture_2 through smart_fixture_8 under [cards]
for additional synthetic fixtures. Use consecutive slots and leave the reader
empty to select another card. The generic coin-slot click remains available.

The automatic contact catalogue includes three generic synchronous read-only
LAB snapshots of 0.50, 5.00 and zero units. They are supplied for contact
memory transport testing, not historical payment authorization. Matching
async snapshots are included for explicit later-board transport tests.
Custom additional contact slot settings override this automatic catalogue.

Calls and troubleshooting
-------------------------

After INSTALL, lift the handset and listen to Voiceware. With the lab free-call
screen installed, dial 18005551212 for a local test without a rate request.

To use SignalWire, copy coinline.example.ini to coinline.ini, fill in your SIP
registrar, username and password, then start Start OEM.cmd. The launcher reports
SIP calling. Use --local for the simulated office or --sip to require SIP settings.
Use the SIP credential's hostname for registrar and its account name for username.
This client uses UDP signaling. It supports G.711 over plain RTP and can accept
incoming G.711 offers that use SDES-SRTP with AES-128. Outbound offers use plain
RTP. Check central-office.log for REGISTER, INVITE, and media negotiation results.
On incoming calls, the log shows when the emulator sends 200 OK and when it
receives the carrier's ACK.
The log also shows the first decoded RTP packet and the reply to a BYE when
you replace the handset.
The handset uses the default Windows recording device. To choose a specific
microphone or virtual mixer output, add an [audio] section to coinline.ini and
set input_device to a unique prefix of its name in Windows Sound > Input.
Set capture_enabled = false under [audio] to avoid opening a recording device.
Restart the emulator after changing the input. The central-office log reports
when microphone signal first reaches the SIP transmit queue.

If the computer is busy, the launcher defaults to a 240 ms host speaker
buffer, automatic artwork frame skipping up to 10, and above-normal Windows
priority for the emulator and local central office. These settings do not
change the terminal clock, analogue signal timing or SIP packet deadlines.
Use --audio-buffer-ms 320 to try a larger speaker buffer, or configure
playback_buffer_ms (40 to 500) under [audio]. Use --max-frameskip 4 to keep
more artwork redraws, or set max_frameskip (0 to 10) under [display].
Zero selects MAME's default automatic limit (10); legacy settings of 11 are
treated as 10 without changing your existing INI file.
Use --host-priority normal, or set host_priority = normal under [performance],
to remove the Windows scheduling preference. Real-time priority is not used.
A buffer absorbs short stalls; it cannot compensate for an emulator that
runs continuously below real time.
Incoming calls ring for two seconds and pause for four seconds. A remote hangup
interrupts the simulated line current so the terminal can end the call.
SIP mode calls the number the terminal outpulses. Dial 10 North American digits
with an optional leading 1, or 011 followed by the international number. Leave
local_address blank for automatic selection. The outbound_digits setting is for
the local office. Use a different local_port if another application owns it.
The launcher also learns the public RTP address from the SIP registrar when
available. If your router uses a fixed UDP mapping for media, set rtp_port to
that port and rtp_public_address to the public IPv4 address.
dtmf_mode = auto prefers negotiated RTP telephone events (RFC 4733), then
explicitly supported SIP INFO, otherwise in-band audio. Use inband or info
only when required by your SIP peer. Local ADSI remains in-band.

For InfoLine, copy adsi-routes.example.ini to adsi-routes.ini and configure
the dedicated service's private IPv4 host and UDP port. Each [adsi.routes]
key is the SIP extension, with a comma-separated list of exact dial aliases.
If a local package already includes adsi-routes.ini, it is configured for the
dedicated service and replaces only ADSI settings for both terminal profiles.
Remove that file to restore each profile's own ADSI settings. Existing
coinline.ini and coinline-graphical.ini SIP accounts and memory are unchanged.
The terminal's installed screening/rating tables must permit the exact aliases.
If four-digit extensions are not accepted by the numbering plan, use their
listed 10/11-digit equivalents. These routes never fall through to the PSTN.
Real firmware
CAS, A, CONNECT, D1 and the welcome menu have been observed within the live
protocol deadlines. With the service's voice-between-screens profile, real
keypad News/Back and softkey Exit passed with clean release; see
docs/status/connected-dtmf-adsi-welcome-2026-11-25.md.

If a CO check fails with 41, check the latest central-office.log under the profile's
logs folder. If NCC fails with 24, verify the listener, matching terminal ID, and
published table set. A card rejected after download usually needs the matching
lab card policy. The OEM firmware can display cents individually and speaks
cents in five-cent increments.

Use --check to check package inputs, --record to save handset WAV audio, or
--headless --seconds 18 for a bounded boot check. The default OpenGL window
adjusts how often it draws to reduce interrupted playback. If the display
driver cannot initialise OpenGL, start with --video gdi for software rendering.
Dragging the title bar or sizing border defers the artwork redraw but keeps
the emulated terminal running. The display catches up when the drag ends.
Each run keeps its emulator log, CO log, and current display under data/<profile>/logs.
The portable launchers keep the debugger and trace sidecars off.
